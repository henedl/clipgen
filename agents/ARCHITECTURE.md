# Architecture

Every module below lives in [source/](../source/). The repo root holds exactly one `.py`
file — the `clipgen.py` launcher — and `tests/test_packaging.py` fails if a second appears.
`source/` is **not** a package (no `__init__.py`); it is put on `sys.path` by the launcher
for real runs and by `tests/conftest.py` under pytest, so every module is imported by bare
name (`import config`).

| File | Role |
| ------ | ------ |
| [clipgen.py](../clipgen.py) | **The repo root's only `.py`.** A launcher: puts `source/` on `sys.path` (skipped when frozen, where PyInstaller bakes the modules into its archive) and calls `cli.main()`. Holds no product logic |
| [app.py](../source/app.py) | Interactive application loop: mode alias table, spreadsheet opening helpers (`open_spreadsheet_by_*`, `select_spreadsheet` — also called by the Studio picker routes), `run_interactive_mode`; delegates to pipeline.py for processing |
| [pipeline.py](../source/pipeline.py) | Clip processing pipeline: process_clips, process_reel, compute_reel_id, regenerate_from_manifest, is_excel_worksheet |
| [viewer.py](../source/viewer.py) | Timeline viewer: artifact record building, data finalization, HTML generation with inlined CSS/JS |
| [cli.py](../source/cli.py) | CLI argument parsing, CLI mode detection, setup, Google auth, worksheet selection, CLI mode dispatch, `main()` |
| [spreadsheet.py](../source/spreadsheet.py) | Spreadsheet parsing, header validation, selector parsing (`reel` input), pure timestamp generation for all modes (no prompts) |
| [interactive.py](../source/interactive.py) | Interactive prompt helpers for all modes (line/range/cell/category/participant selection, browse mode); keeps generation functions pure |
| [video.py](../source/video.py) | ffmpeg/ffprobe operations: cut clips, screenshots, GIFs, concatenate reels, optional filesize compression |
| [transcripts.py](../source/transcripts.py) | Transcription via faster-whisper: `transcribe_video()`, segment filtering, write/read transcript files (Markdown/SRT/VTT) |
| [transcripts_server.py](../source/transcripts_server.py) | Transcripts Flask blueprint and thinking-agent orchestrator: `_next_eligible_agent()`, `_run_agent()`, `_run_agent_chain()`, `_agent_in_flight` tracking, REST endpoints |
| [ollama_client.py](../source/ollama_client.py) | Ollama HTTP transport: `is_available()`, `list_models()`, `generate()`, auto-start of `ollama serve`. Pure transport. No prompt or response-parsing logic lives here. |
| [thinking_agents.py](../source/thinking_agents.py) | Registry of Ollama-powered "thinking agents" that reason over transcripts (summary, citations, friction). Owns prompt assembly, model selection, response parsing, and the `AGENTS` list. Default prompt **text** lives in `config.py` as `OLLAMA_*_PROMPT`/`OLLAMA_*_SYSTEM` settings (user-editable in Settings → Summaries) and is read at call time. New agents are added by appending an `Agent` entry. No orchestrator edits needed. |
| [friction.py](../source/friction.py) | Pure deterministic friction scorer: compiled phrase patterns across six categories, per-segment score/markers, candidate selection, session stats (the timeline heatmap's rolling-window smoothing is client-side, in `transcripts-video.js`). No Ollama/I/O. The LLM refinement (`find_friction_moments`, `_run_friction`) lives in thinking_agents.py. |
| [titlecards.py](../source/titlecards.py) | Titlecard/endcard generation: `build_titlecard_frame()`, `build_endcard_frame()`, `wrap_clip_with_cards()`. Prepends a title card and appends an endcard in a single FFmpeg encode pass |
| [files.py](../source/files.py) | Filename handling (unique names, truncation), `prepare_clip()` (parse timestamps + annotations, sanitize desc/category), clip discovery for reel-late, and `resolve_participant_videos()` — the one participant list every web tool shows: the sheet's columns (override-aware, missing files kept as `has_video: false`) unioned with whatever `utils.discover_participant_videos()` finds on disk, each entry flagged `in_sheet`. A disk-only participant keeps its own discovered path; it is never re-resolved against the sheet's study name |
| [utils.py](../source/utils.py) | Timestamp parsing, cell/header annotation parsing, rich/plain output helpers, progress bar utilities, keyword-aware input helpers |
| [config.py](../source/config.py) | Global constants and settings (version, headers, limits, commands) |
| [google_api.py](../source/google_api.py) | Google Sheets auth, worksheet selection by priority, spreadsheet listing/search |
| [excel_io.py](../source/excel_io.py) | Excel adapter: `ExcelSheetAdapter` mimics gspread Worksheet interface for local .xlsx |
| [server.py](../source/server.py) | Combined Flask server for Studio + Screenspace + Transcripts + Workflows; registers all blueprints (always mounted, mutually exclusive launch), `start_combined_server()` handles them on one port |
| [desktop.py](../source/desktop.py) | Native desktop window host: wraps `server.serve_combined_app` in a pywebview window (WKWebView on macOS, WebView2 on Windows) so a frozen bundle opens as an app instead of a Terminal + browser tab. Only an argument-less frozen launch (or `--desktop`) uses it; every explicit CLI invocation is untouched. Also owns the two JS bridges the embedded engine needs — `open_external` (a webview has no back button) and `save_file` (WKWebView silently drops *every* download: blob:, data:, and HTTP `Content-Disposition` alike). Remembers the window rect across launches in `start.json` (`_window_kwargs` refuses to restore a position that is no longer on any screen; holding Shift at launch resets to the default size) |
| [desktop_chrome.py](../source/desktop_chrome.py) | macOS window chrome for that host: hides the native title bar (`NSFullSizeContentViewWindowMask` + transparent, untitled titlebar) so web content runs to the top of the window, and re-centers the traffic lights inside the topnav by growing the `NSTitlebarContainerView` — AppKit resets that on resize and on leaving fullscreen, hence the notification observers. Deliberately *not* pywebview's `frameless=True`, which hides the lights. Dragging is the frontend's job: `-webkit-app-region` does nothing in WKWebView, so `topnav.js` opts into pywebview's `.pywebview-drag-region` selector instead. The page learns it is in a native window from `html[data-desktop-chrome]`, written by `utils.render_index_html()` — `window.pywebview` is injected too late to lay out against. Inert off macOS; every failure degrades to the standard title bar |
| [screenspace.py](../source/screenspace.py) | Screenspace re-export facade: a thin module that re-exports every public name (and the test-touched private names) from the nine `screenspace_*` modules below, so `import screenspace; screenspace.NAME` keeps working unchanged. Holds the engine's 13-tool overview docstring; no implementation |
| [screenspace_primitives.py](../source/screenspace_primitives.py) | Pure cv2/numpy/PIL image-analysis primitives: region crop/denormalize/resolve, HSV color math, frame-diff, SSIM, perceptual hash, template matching, optical flow, scene fingerprinting, plus scan-support helpers (`_morph_kernel`, `_ConsecutiveBuffer`, `_is_static_skip`, `_merge_timestamp_spans`). No I/O or ffmpeg |
| [screenspace_ocr.py](../source/screenspace_ocr.py) | Cached EasyOCR readers, region preprocessing, glyph confusion-folding, numeric comparison helpers/allowlists, region reading/scoring, and `run_calibration_ocr`. Imports primitives |
| [screenspace_frames.py](../source/screenspace_frames.py) | ffmpeg-pipe frame extraction (`scan_video_frames`/`scan_video_full_frames`, `_ffmpeg_pipe_frames`), timelapse command builder, ffprobe metadata. Imports primitives |
| [screenspace_scans.py](../source/screenspace_scans.py) | The twelve per-tool scan workflows (`scan_color`…`scan_attention`, `generate_timelapse`); scans never call each other. Imports primitives, ocr, frames |
| [screenspace_heatmap.py](../source/screenspace_heatmap.py) | Template/flow/change/attention heatmap PNG + animated-GIF generation (cumulative + rolling-window). Pure cv2/PIL leaf, no sibling-module deps |
| [screenspace_tools.py](../source/screenspace_tools.py) | `AnalysisTool` base + thirteen tool subclasses, the `TOOLS` registry, and per-frame dispatch (`check_frame_for_tool`, `score_frame_for_tool`). Imports primitives, ocr, scans; one function-local import of `scan_multitool` in `MultitoolTool.scan` breaks the tools↔multitool cycle |
| [screenspace_multitool.py](../source/screenspace_multitool.py) | Multitool chaining + time-offset window joining (`scan_multitool`, `score_multitool_frame`). Imports tools + frames |
| [screenspace_manifest.py](../source/screenspace_manifest.py) | Task-status constants, `create_task`, manifest load/save, result-time offsetting, and event generation. Imports tools (`_extract_confidence`) |
| [screenspace_worker.py](../source/screenspace_worker.py) | `ScreenspaceWorker` background task queue (threading, pause/resume/cancel, multi-video, heatmaps, events). Imports tools, heatmap, manifest, multitool, frames |
| [screenspace_preview.py](../source/screenspace_preview.py) | Model-view preview renderer: `build_preview` (labeled multi-panel composite) + `build_overlay_layer` (single region/frame layer, catalogued in `OVERLAY_LAYERS`) show what each tool's CV pipeline actually operates on. Must mirror the real scan's preprocessing (e.g. binarized template mask via `_prepare_template`). Pure cv2/numpy leaf; imports primitives + ocr; consumed only by `screenspace_server.py`'s `/api/preview` routes |
| [screenspace_server.py](../source/screenspace_server.py) | Screenspace Flask REST API: region CRUD, video frame extraction, task queue management, results retrieval |
| [workflows.py](../source/workflows.py) | Workflows node-graph engine: the per-node `_EXECUTORS` + collection-algebra control nodes, the import-time wiring that attaches `execute` keys to the shared `NODE_TYPES` dict, and the re-export facade over `workflows_catalog`/`workflows_runner` (import DAG: catalog → runner → workflows; `import workflows` before running graphs). Orchestration-only. Reuses pipeline/screenspace/transcripts/viewer, never reimplements them |
| [workflows_catalog.py](../source/workflows_catalog.py) | Declarative workflows data: `NodeContext`, the `NODE_TYPES` registry (typed ports + param schema), `BUILTIN_STASHES`, source-descriptor helpers, and the typed-port `ADAPTERS` table. Imports only config/utils (late-imports files/video inside adapters); unwired until workflows.py's import-time wiring runs |
| [workflows_runner.py](../source/workflows_runner.py) | Workflows run engine: run/node status constants, trigger types, `topo_order`, `bind_participant`, per-node result sidecars, `compute_resume_plan`, and `WorkflowRunner` (topo-sorted DAG execution). Reads `NODE_TYPES[...]["execute"]`/`ADAPTERS` only at call time, after the facade's wiring |
| [workflows_server.py](../source/workflows_server.py) | Workflows Flask blueprint: blueprint/stash CRUD, run + whole-study batch lifecycle (SSE + polling), per-node result sidecars, and the auto-run trigger daemon (single-armed per trigger type: new video / transcript complete / scan complete) |
| [composer_server.py](../source/composer_server.py) | Composer Flask blueprint: source-video cutting timeline. Participant/part discovery (stitched multi-part timelines), `composer_manifest.json` CRUD (cut pairs, marker trims, annotations, UI state), PIL annotation rendering, and annotated screenshot/GIF/burn exports (ffmpeg `overlay`, never `drawtext`). Cut pairs feed generation through Studio's `/api/generate-intake`; never writes the spreadsheet |
| [overview.py](../source/overview.py) | Overview frontend: per-participant feature-matrix builders for the Map similarity space (`build_feature_matrix` + the four `build_*_features` group builders; observations fed by sheet timestamps via the `configure()`-injected getter), the `/overview/` blueprint, and the convergence-offsets + friction-moments routes. Pure-Python (no numpy); the client does z-scoring/PCA/outlier math |
| [data_export.py](../source/data_export.py) | Analysis-ready JSON+CSV export from Screenspace and Transcripts manifests; powers `--export` CLI flag and `/screenspace/api/export/events` endpoint |
| [server_utils.py](../source/server_utils.py) | Shared Flask scaffolding for all four blueprints: the uniform `{"ok": ...}` envelope (`ok`/`err`), `ApiError` + the `json_endpoint` decorator, `parse_number_arg` bound-checking, the bounded LRU `MediaCache`, `parse_clip_window`, `make_debounced_persist` (the manifest-write debounce), and `make_sse_channel`. Reach for these rather than re-deriving the guard block per route |
| [start_settings.py](../source/start_settings.py) | Per-user persistence: last-used input/output directories and spreadsheet, capped at `RECENTS_CAP` entries, plus the desktop window rect, with a user-facing `persist_enabled` toggle that is still written when persistence is off. Stored at `%LOCALAPPDATA%\clipgen\start.json` on Windows, `~/.config/clipgen/start.json` elsewhere. Every mutating helper holds `_write_lock` across the whole load→mutate→save (saves rewrite the entire dict, and the desktop debounce timer writes concurrently with Flask request threads) |
| [changelog.py](../source/changelog.py) | Parses `CHANGELOG.md` level-2 headings (`## <version> — <date> — <tool>`) into structured entries for the Start overlay. File order wins; no re-sorting by version. `tests/test_changelog.py` guards the shape |
| [assets/web/](assets/web/) | Static HTML/JS/CSS templates: timeline viewer (`viewer.html/js/css`), gallery (`gallery.html/js/css`), studio (`studio.html/js/css`), screenspace (`screenspace.html/js/css`), transcripts (`transcripts.html/js/css`). Shared utilities and constants live in `utils.js` (loaded before each page's main script). The Screenspace page is split across a hub (`screenspace.js`) plus state-free leaf helpers (`screenspace-utils.js`) and nine satellite files — `screenspace-tasks.js` (task queue + right-pane tabs + SSE/polling + ETA), `screenspace-results.js` (results panel: confidence histogram, rows, heatmap overlay), `screenspace-overlay.js` (region-editor canvas painter), `screenspace-overlay-interaction.js` (region draw/drag/resize state machine + region toolbar + overlay-rect cache), `screenspace-timeline.js` (event timeline + playhead), `screenspace-model-view.js` (live preprocessed-frame preview + overlay-layer UI), `screenspace-multitool-params.js`, `screenspace-calibration.js`, `screenspace-color.js` — that share the hub's state and helpers through a `window.ClipgenScreenspace` namespace. The Transcripts page is split the same way: a `transcripts.js` hub plus `transcripts-{corrections,search,video,pills,agents}.js` satellites sharing state through `window.ClipgenTranscripts` (TS). The hub keeps `state`, the cross-reference index, `selectParticipant`, the segments+marks editor, the transcription/agent task poller, and model-install, reaching satellite functions through same-named guarded delegators. There is no `transcripts-utils.js` — unlike Screenspace there was no shared pure-helper cluster, and `showToast` stays hub-local so its 2500 ms override doesn't leak onto `start-overlay`'s global. The Studio page follows the same axis: a `studio.js` hub plus `studio-{intake,generate,trim,stash,scrubber}.js` satellites (Screenspace + Transcript intake panels; the streaming generate flow; the duration-badge trim pop-over; the reel/artifact stash panels; hover-to-scrub card wiring) sharing state through `window.ClipgenStudio` (STUDIO) with same-named guarded delegators (the old `window._studio*` legacy globals are gone; their readers moved to the Overview page). `buildXrefBadges` / `xrefBadgeIcon` are `utils.js` ambient globals, shared with Overview. The Overview page is its own hub+satellite group: an `overview.js` hub (shared state, memoized cross-prefix bootstrap fetches, tab switching) plus `overview-{map,convergence,metadata}.js` tab satellites sharing state through `window.ClipgenOverview` (OV); its Map tab renders WebGL via the vendored Three.js r147 UMD build in `assets/web/vendor/` (the only third-party JS; see vendor/README.md). `card-scrubber.{js,css}` provides reusable hover-to-scrub: sprite-sheet frame scrubbing + synced audio snippets + a waveform/playhead overlay (exposes `window.clipgenCardScrubber`). Opt-in on two surfaces: Studio (settings toggle `STUDIO_CARD_SCRUBBER`, backed by the `/api/sprite` + `/api/clip-audio` routes) loads it directly; the timeline viewer (header toggle, localStorage `clipgen-viewer-scrubaudio`) layers its audio/waveform primitives onto the existing `<video>`-seek scrub and inlines the module via `viewer.py`. The Workflows page follows the same hub+satellite pattern: a `workflows.js` hub plus `workflows-{nodes,canvas,wires,runs,stashes,validate}.js` satellites sharing state through `window.ClipgenWorkflows` (WF). The Composer page likewise: a `composer.js` hub (state, API client, multi-part `<video>` playback, keyboard, cut list, intake generation, undo/redo, exports) plus `composer-{markers,timeline,annotate}.js` satellites sharing state through `window.ClipgenComposer` (CO). |

> Subsystem internals (data contracts, key function signatures, merge/dedup rules) live in each module's docstring. The sections below describe how each subsystem is launched and how it fits into the overall flow; for internals, open the referenced module.

## Timeline HTML Viewer ([viewer.py](../source/viewer.py))

Opt-in via `--viewer` or interactive `viewer`. Injects `window.CLIPGEN_DATA` into `assets/web/viewer.html` replacing `<!-- CLIPGEN_DATA_HERE -->`.

## Gallery HTML Viewer ([viewer.py](../source/viewer.py))

Opt-in via `--gallery [VIDEO]` or interactive `gv`/`gallery`. Uses the same injection pattern as the timeline viewer but with `assets/web/gallery.html`.

## Studio Web Interface ([server.py](../source/server.py))

Opt-in via `--studio`; requires a spreadsheet. Starts a Flask app via `start_combined_server()` at `config.SERVER_PORT` (8089), serving `assets/web/studio.html`.

## Screenspace ([screenspace.py](../source/screenspace.py) facade over `screenspace_primitives`/`_ocr`/`_frames`/`_scans`/`_heatmap`/`_tools`/`_multitool`/`_manifest`/`_worker`, [screenspace_server.py](../source/screenspace_server.py))

Opt-in via `--screenspace` or interactive `ss`/`screenspace`; no spreadsheet required. Served at `/screenspace/` by the combined Flask server. The engine ships twelve scan workflows and thirteen `AnalysisTool` classes (the nine region detectors plus the full-frame `boundary` and `attention`, `timelapse`, and `multitool`); `screenspace.py` is a thin re-export facade and the implementation lives in the cohesive `screenspace_*` sibling modules listed above, wired in an acyclic deepest-first DAG (`primitives`/`heatmap` → `ocr` → `frames` → `scans` → `tools` → `multitool`/`manifest` → `worker`). The browser UI is split the same way — a `screenspace.js` hub plus satellites sharing state through `window.ClipgenScreenspace`; the file-by-file inventory is in the `assets/web/` row above.

## Overview ([overview.py](../source/overview.py))

Opt-in via `--overview` (or reachable from the top navigation in any launch; always mounted by the combined server); no spreadsheet required. Three cohort-level tabs: **Map** — a 3D similarity space (participants positioned by deterministic client-side PCA over weighted, z-scored feature vectors built server-side from sheet timestamps + the screenspace/transcripts manifests; outlier halos, click-to-explain with per-feature muting, similarity/anchor/point-cloud layers, drill-down burst + timeline drawer, and a session-replay glow); **Convergence** — the cross-participant timeline browser (moved from Studio; per-participant alignment offsets persist via `GET/PUT /overview/api/convergence/offsets`); **Metadata** — cohort aggregate statistics (moved from Studio; drill-downs link to `/studio/`). The browser UI is an `overview.js` hub plus `overview-{map,convergence,metadata}.js` satellites sharing state through `window.ClipgenOverview` (OV); the hub bootstrap-fetches sheet/baseline/events/marks cross-prefix once (memoized behind a `dataVersion` counter — the tabs' staleness banners compare *versions*, never list lengths; Refresh re-runs it, and every fetch degrades gracefully with no spreadsheet/scans/transcripts). No pollers. **Route placement is deliberate:** the convergence-offsets and friction-moments routes live on the overview blueprint so the satellites' page-relative `apiGet("api/...")` calls resolve, while sheet/baseline/thumbnail stay on the studio blueprint and are called as `../studio/api/...`. `/transcripts/#P07`-style hashes (emitted by the Map explain panel, parsed by `clipgenHashParticipant()` in `utils.js`) pre-select a participant on the target page. The Map tab uses the vendored Three.js r147 UMD build (`assets/web/vendor/three.min.js`, the only third-party JS; do not upgrade, newer releases are ESM-only).

## Workflows ([workflows.py](../source/workflows.py) engine, [workflows_server.py](../source/workflows_server.py) blueprint)

Opt-in via `--workflows`; no spreadsheet required. Served at `/workflows/` by the combined server. A node-graph canvas chains the clip / Screenspace / transcript / thinking capabilities into a DAG: declarative `NODE_TYPES` + per-node `_EXECUTORS` + typed-port `ADAPTERS`, run in topological order by `WorkflowRunner` (per-node status/notes, inspectable result sidecars under `<output_dir>/workflow_runs/<run_id>/`). A blueprint can fan out across every participant (whole-study batch, sequential by default with opt-in `WORKFLOWS_BATCH_WORKERS` parallelism) or auto-run on a trigger — a new video landing in `-i`, a transcript completing, or a Screenspace scan completing (one armed blueprint per trigger type; the poll does no I/O while nothing is armed). Failed runs can resume from their per-node result sidecars (`resumeFromRunId`). The browser UI is a `workflows.js` hub plus `workflows-{nodes,canvas,wires,runs,stashes,validate}.js` satellites sharing state through `window.ClipgenWorkflows` (WF). Built-in recipes ship as read-only `BUILTIN_STASHES`. Phased build history: [plans/archive/WORKFLOWS-PHASE2-PLAN.md](../plans/archive/WORKFLOWS-PHASE2-PLAN.md), [plans/archive/WORKFLOWS-PHASE3-PLAN.md](../plans/archive/WORKFLOWS-PHASE3-PLAN.md).

## Composer ([composer_server.py](../source/composer_server.py))

Opt-in via `--composer`; no spreadsheet required. Served at `/composer/` by the combined server. A full-source-video cutting timeline per participant: multiple named in/out cut pairs (hotkeys `i`/`o` or timeline double-clicks, gated by the `COMPOSER_DOUBLE_CLICK_CUTS` setting; draggable edges, undo/redo) on a single cuts track, three toggleable/foldable read-only marker lanes (Sheet timestamps / Screenspace events / Transcript marks, fetched cross-blueprint like `convergence.js` and aligned via the Convergence per-lane offsets), **non-destructive marker trims** (drag a marker's edge; the override persists as `trims[key]` in the composer manifest and the source manifests are never touched; right-click resets), and clip generation through Studio's streaming `/api/generate-intake`. All state persists to `composer_manifest.json`; the spreadsheet is never written. Studio has a **Composer Intake** tab (`CO_INTAKE` in `studio-intake.js`, source `"composer"`) that polls the composer manifest and feeds named cuts + trims into the Artifact/Reel queues. The **annotation layer** (P3): text labels, freehand strokes + rotatable rect/ellipse shapes drawn on a letterbox-aware canvas over the `<video>` (`composer-annotate.js`), each with a visibility span shown as its own timeline lane; geometry is normalized 0..1 so the live preview matches the server's PIL render (`_render_annotation_overlay`, no ffmpeg `drawtext`); exports (`/api/export/screenshot|burn|gif`) composite/burn via the ffmpeg `overlay` filter with span-relative `enable='between(t,...)'` windows and land in `clipgen_manifest.json`.

## Artifact Manifest ([viewer.py](../source/viewer.py))

Opt-in via `--manifest` or `config.MANIFEST_ENABLED`. Writes `clipgen_manifest.json` alongside artifacts. Key functions: `save_manifest`, `load_manifest_artifacts`, `load_manifest_both` (reels are its second return value). Consumed by `--regenerate` and standalone `--viewer`.

## Transcription ([transcripts.py](../source/transcripts.py))

Opt-in via `--transcribe` or `config.TRANSCRIBE_ENABLED`. Uses faster-whisper; model is lazy-loaded and cached per session.

## Local AI: Ollama thinking-agent pipeline ([ollama_client.py](../source/ollama_client.py), [thinking_agents.py](../source/thinking_agents.py), [transcripts_server.py](../source/transcripts_server.py))

Two layers, kept strictly separate:

1. **Transport** — [ollama_client.py](../source/ollama_client.py) is a thin HTTP wrapper around the Ollama REST API. Every LLM call in the project routes through `ollama_client.generate()`. It knows nothing about prompts, transcripts, or parsing. On connection-refused it auto-starts `ollama serve` and retries once.
2. **Agents** — [thinking_agents.py](../source/thinking_agents.py) defines the `Agent` shape (prompt building + model selection + response parsing + `depends_on` metadata + target `manifest_field`) and exports an ordered `AGENTS` list. The built-in agents are `summary` (Pass 1: paragraph + bullets), `citations` (Pass 2: supporting segments per claim, depends on `summary`), and `friction` (Pass 3: deterministic scorer in [friction.py](../source/friction.py) + LLM-refined moments, depends on `summary`, runs even when citations is disabled).

**Orchestration** lives in [transcripts_server.py](../source/transcripts_server.py) as three small helpers: `_next_eligible_agent()`, `_run_agent()`, `_run_agent_chain()`. When a transcript completes (or a user hits Regenerate), the chain is re-entered and the first eligible agent is spawned in a daemon thread. An agent is eligible when it is enabled in config, its `manifest_field` is empty on the transcript entry, its `depends_on` agents' fields are populated, and it is not already running for that participant. After each agent finishes, the chain advances.

Results are written into `source_transcripts[participant][manifest_field]` in `transcripts_manifest.json`. In-flight tracking is keyed per-agent via `_agent_in_flight[agent_key]`, surfaced to the frontend through generic `_is_generating(participant, agent_key)` checks at the API endpoints.

**Adding a new agent**: see [agents/skills/new-thinking-agent/SKILL.md](skills/new-thinking-agent/SKILL.md). The orchestrator picks up new agents from the `AGENTS` list automatically. No edits to [transcripts_server.py](../source/transcripts_server.py) or [ollama_client.py](../source/ollama_client.py) are needed.

## Titlecards ([titlecards.py](../source/titlecards.py))

Opt-in via `config.TITLECARDS_ENABLED` or `--titlecards` / `--no-titlecards`. Prepends a title card (first source frame + text overlay) to each clip.
