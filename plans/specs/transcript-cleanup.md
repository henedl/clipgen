# Transcript Cleanup Pipeline — clipgen

## Overview

Clipgen's transcript layer should follow the same **deterministic pre-pass → LLM → deterministic post-pass** architecture used by ghost-pepper. The LLM is the expensive middle step; the surrounding passes handle high-confidence substitutions cheaply and make the LLM's job smaller and more reliable.

The goal is to produce clean, readable transcripts from Whisper output that can be:
- Stored alongside clips in the manifest
- Used as navigation/search within Studio
- Fed back into Screenspace for event label disambiguation

---

## Model Selection

Use **Qwen 3 0.6B or 1.7B** (MLX-quantized) via `mlx_lm` or `llama-cpp-python`.

Rationale:
- Ghost-pepper's 0.8B default achieves acceptable quality at ~1–2s latency. UX research transcripts are typically longer than dictation inputs, so a 1.7B may be warranted.
- Both sizes run entirely locally on Apple Silicon, consistent with clipgen's local-first design.
- Qwen 3 supports `<think>` reasoning blocks — strip these in post-processing (see ghost-pepper's `sanitizeCleanupOutput` pattern).
- CPU-only inference is viable for batch processing (no GPU required in CI); keep `mlx` for interactive use and `llama-cpp` as a fallback for non-Apple hardware.

---

## Pipeline Architecture

```
Whisper output
     │
     ▼
[1] Pre-pass: DeterministicCorrector
     │   - Apply corrections dictionary (wrong → right)
     │   - Apply preferred transcriptions (preserve-exactly terms)
     │   - Normalise numbers, times, dates
     │
     ▼
[2] LLM cleanup (Qwen 3)
     │   - System prompt (see below)
     │   - Input wrapped in <USER-INPUT> tags
     │   - Strip <think> blocks from output
     │
     ▼
[3] Post-pass: DeterministicCorrector
     │   - Re-apply preferred transcriptions (catch LLM drift)
     │   - Normalise any formatting the LLM introduced
     │
     ▼
Clean transcript
```

If the LLM is unavailable or returns unusable output, fall back to deterministic-only and log it. Never block clip generation on transcript cleanup failure.

## System Prompt

Adapted from ghost-pepper's `defaultPrompt` for the UX research context.

```
Your job is to clean up transcribed audio from a UX research session.
The audio transcription engine can make mistakes and will sometimes
transcribe things in a way that is not how they should be written in text.

Repeat back EVERYTHING that was said.

Your FIRM RULES are:
1. Delete filler words: um, uh, like, you know, basically, literally, sort of, kind of.
2. ONLY if the speaker says the EXACT phrases "scratch that", "never mind", or
   "no let me start over", delete what they are correcting. Otherwise keep wording
   and meaning the same.
3. Correct obvious recognition misses for product names, feature names, UI labels,
   task names, and participant/facilitator names when context clearly shows the
   intended term.
4. Fix obvious typographical errors. Do not fix turns of phrase.
5. Clean up punctuation. Sentences should be properly punctuated.
6. Output should appear to be competently and professionally written, as a human
   would normally type it.
7. If the speaker is manually inserting punctuation or spelling something out,
   honour that.
8. Do not change the speaker's word selection unless you believe the transcription
   was in error.
9. You must reproduce the entire transcript of what was said.

CRITICAL: Do NOT delete sentences. Do NOT remove context. Do NOT summarise.
If you are unsure whether to keep or delete something, KEEP IT.

<EXAMPLES>
Input: "So um the the task was to find the checkout button you know"
Output: So the task was to find the checkout button.

Input: "I clicked on settings and then I was like, where's the thing? Scratch that. I found it under profile."
Output: I found it under profile.

Input: "It took me like four or five tries to get it to work"
Output: It took me 4 or 5 tries to get it to work.

Input: "What happens if I click cancel?"
Output: What happens if I click cancel?
</EXAMPLES>
```

If session-specific context is available (product name, feature list, participant names), append it as an additional section:

```
<SESSION-CONTEXT>
Product: [product name]
Features mentioned in this session: [list]
Participant name: [name], Facilitator name: [name]
</SESSION-CONTEXT>
```

## Corrections Dictionary

Structured as two lists, injected via `<CORRECTION-HINTS>`:

**`commonly_misheard`** — wrong → right substitutions applied in pre-pass:
```
clip gen → clipgen
screen space → Screenspace
G sheets → Google Sheets
```

**`preferred_transcriptions`** — preserve-exactly terms re-applied in post-pass:
```
clipgen
Screenspace
ffmpeg
```

Store these in the same format as other Corrections generated by users in the Transcript frontend.

## Input/Output Format

Wrap the input consistently so the model has a stable template:

```python
def format_input(text: str) -> str:
    return f"<USER-INPUT>\n{text}\n</USER-INPUT>"
```

Strip `<think>` blocks from output before any further processing:

```python
import re

THINK_BLOCK = re.compile(r"(?is)<think\b[^>]*>.*?</think>")
LEADING_THINK = re.compile(r"(?is)^\s*<think\b[^>]*>")

def strip_think_blocks(text: str) -> str:
    text = THINK_BLOCK.sub("", text)
    m = LEADING_THINK.match(text)
    if m:
        text = text[:m.start()]
    return text.strip()
```

## Screenspace Integration

The cleaned transcript feeds Screenspace's event detection in two ways:

**Timestamp anchoring** — pair each Whisper word-level timestamp with the cleaned text to produce a time-aligned transcript. This lets Screenspace events reference transcript spans, not just frame positions.

**Event label disambiguation** — when a CV detector fires on a screen region, feed the transcript window (±5s) as context to the cleanup model with a modified prompt asking it to confirm or refine the event label. This mirrors ghost-pepper's OCR grounding pattern but inverted: video events ground the transcript rather than screen text grounding speech.

---

## Chunking Strategy

Whisper produces per-segment output. Process at the **segment level**, not the full transcript, to:
- Keep LLM context windows small (faster, cheaper)
- Preserve segment-level timestamps for Studio navigation
- Allow incremental processing as clips are generated

Segments shorter than ~3 words can skip the LLM pass and go deterministic-only.
